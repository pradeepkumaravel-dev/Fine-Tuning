# Fine-Tuning Lab

A hands-on notebook that fine-tunes [Qwen2.5-0.5B-Instruct](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct) with **LoRA** on a 4GB laptop GPU — no cloud, no quantization tricks, just `transformers` + `peft` and a small VRAM budget.

It's split into two parts: how tokenization works, then how LoRA fine-tuning actually updates a model.

## What it does

The notebook fine-tunes the base model to always answer in pirate voice, as a toy task chosen specifically because the effect is immediately obvious — no rigorous eval needed to see whether it worked.

**Before fine-tuning:**
> As an AI language model, I don't have access to real-time information or current weather conditions. However, you can check the weather forecast on a trusted website or app in your region for up-to-date and accurate information about the weather conditions.

**After fine-tuning (LoRA adapter enabled):**
> Arrr, the skies be grey and the wind bites like a hungry shark, matey!

And it generalizes to prompts never seen during training:
> Arrr, arrr, ye landlubber, for no clock survives the salty sea air!

Swap the toy dataset for your own instruction/response pairs and the rest of the pipeline works unchanged.

## Why this is interesting

Full fine-tuning updates every weight in the model, which needs far more than 4GB of VRAM even for small models. **LoRA** (Low-Rank Adaptation) instead freezes the entire base model and injects small trainable matrices into a handful of layers — only ~1.7% of parameters (~8.8M of 502M) get trained here, which is what makes this feasible on a laptop GPU:

| | Full fine-tuning | LoRA (this repo) |
|---|---|---|
| Weights updated | All ~500M | ~8.8M (adapter only) |
| Saved artifact | Full model copy (~1GB+) | ~35MB adapter |
| Peak VRAM (RTX 3050) | Would not fit in 4GB | ~1.3GB |

## What's inside

- **Part 1 — Tokenization**: encode/decode, byte-pair encoding and subword splitting, special tokens (BOS/EOS/PAD/UNK), batching/padding/attention masks, comparing tokenizers across GPT-2/BERT/Qwen, and chat templates.
- **Part 2 — Fine-tuning with LoRA**: baseline generation, building and tokenizing a training set (with `-100` label masking so loss only applies to the response, not the prompt), configuring a `LoraConfig`, training with `Trainer` under a tight VRAM budget (gradient checkpointing, gradient accumulation, bf16/fp16), saving the adapter, and a genuine before/after comparison using `disable_adapter()`.

## Hardware

Built and tested on an RTX 3050 Laptop GPU (4GB VRAM) + 16GB RAM. Peak VRAM during training: ~1.3GB, so this comfortably fits — there's headroom to push `target_modules`, rank, or model size further. See "Where to go from here" at the end of the notebook for scaling to bigger models with 4-bit quantization (QLoRA).

## Setup

Dependencies are managed with [`uv`](https://docs.astral.sh/uv/) in an isolated `.venv` — nothing is installed globally.

```bash
# Install uv if you don't have it: https://docs.astral.sh/uv/getting-started/installation/
uv sync
```

This resolves a CUDA-enabled PyTorch build (cu121) via the pinned index in `pyproject.toml`. If you don't have an NVIDIA GPU, `uv sync` still works — Part 1 (tokenization) runs fine on CPU, and Part 2 will just be much slower.

### Run it

**VS Code**: open `learning_fine_tuning.ipynb`, pick the `.venv` interpreter as your kernel, and run cells top to bottom.

**Jupyter Lab**:
```bash
uv run jupyter lab
```

Register the kernel once if it doesn't show up automatically:
```bash
uv run python -m ipykernel install --user --name fine-tuning-lab --display-name "Python (fine-tuning-lab)"
```

## Project structure

```
learning_fine_tuning.ipynb   # the notebook — start here
generate_notebook.py         # source of truth that generates the notebook (nbformat)
pyproject.toml / uv.lock     # dependencies, pinned CUDA torch index
```

Running the notebook creates `pirate-lora-adapter/` (the trained LoRA adapter) and `pirate-lora-checkpoints/` (training scratch space) — both are gitignored since they're regenerated by re-running Part 2.

## Stack

`transformers` · `peft` (LoRA) · `datasets` · `accelerate` · `trl` (installed, for exploring `SFTTrainer`) · `uv`
